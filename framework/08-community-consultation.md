# Chapter 8: Community Consultation

*The AI Threat Modeling Framework*

---

## Workshop facilitation guide

*Discovery workshop: "What traditional threat modeling misses in AI-enabled systems"*

### Objectives

- Surface practitioner pain points and missed failures
- Validate candidate values and principles
- Collect examples for pilot documentation
- Build multidisciplinary relationships

### Duration

90–120 minutes

### Participants (8–15 people)

Minimum representation: threat modeling/security, AI/ML engineering, product or domain, one of privacy/safety/legal, operations.

### Agenda

| Time | Activity | Facilitator notes |
|------|----------|-------------------|
| 0:00–0:10 | Welcome, goals, code of conduct | No vendor pitches |
| 0:10–0:25 | Scenario walkthrough (pick one from [Chapter 7 pilot scenarios](07-putting-it-into-practice.md#pilot-scenarios)) | Ask "what would your TM miss?" |
| 0:25–0:45 | Breakout: failure stories | Prompt: post-deploy surprises |
| 0:45–1:05 | Values card sort | Rank [candidate values](03-values.md) |
| 1:05–1:20 | Principle gap analysis | Which principles would have helped? |
| 1:20–1:30 | Wrap: commitments and follow-up | Invite pilot volunteers |

### Key questions

1. What failure did an existing threat-modeling method miss?
2. What changed after deployment that invalidated the original model?
3. Where did effective authority exceed documented authority?
4. Which control depended on model cooperation and failed?
5. What principle would have changed the design decision early enough?

### Outputs

- Anonymized notes for framework maintainers (see [Contributing](../README.md#contributing))
- Prioritized backlog for framework drafting
- Pilot volunteer list

### Materials

- [Threat modeling canvas](threat-modeling-canvas.md) (printed or digital)
- [README](../README.md) one-pager
- Sticky notes or collaborative board
